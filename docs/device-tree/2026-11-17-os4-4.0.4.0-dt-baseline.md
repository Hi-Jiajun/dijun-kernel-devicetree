# OS4.0.4.0 设备树基线、目录防误判重构与 `.dtso` 增量开发流（2026-11-17）

## 1. 为什么必须重构 `dts/` 目录命名

原仓库顶层目录 `dts/` 存放的是小米早期开源的 `dijun-v-oss`（Android 15 / Linux `6.6.30`，base model `XiaoMi Franklin1 Basic`），而真机 OS3/OS4 实际运行的设备树位于 `dts-reconstructed/`。

在后续跨系统适配排查中，出现过直接读取 `dts/` 作为“当前 6.18.32 基线”的误判（例如开源 6.6.30 中的部分外设启用状态与 OS4 真机完全不同，真实 OS4 `base.dts` 中 `xrisp_flash_sgm37864@63` 为 `status = "disable"`）。为此做出硬性结构隔离：

- `dts/` → `dts-oss/6.6.30-android15-v/`，内附显式警告 `README.md`；
- `dts-current` → 相对软链指向现行真机基线 `dts-reconstructed/6.18.21-os4.0.4.0/`；
- `dts-reconstructed/` 与 `baseline/` 按 `6.6.118-os3`、`6.18.21-os4.0.0.19`、`6.18.21-os4.0.4.0` 三代分目录管理，各代同时反编译并校验全部 8 个 `dtbo/entry*.dtbo`（不仅是单枚 `o2s_phone_overlay.dtbo`）。

## 2. `OS4.0.0.19` → `OS4.0.4.0` 精确设备树差异

基于修复后的 `tools/fdtdiff.py`（见 [`docs/reports/os4.0.0.19-vs-os4.0.4.0-base.txt`](../reports/os4.0.0.19-vs-os4.0.4.0-base.txt) 与 [`docs/reports/os4.0.0.19-vs-os4.0.4.0-entry07.txt`](../reports/os4.0.0.19-vs-os4.0.4.0-entry07.txt)）：

- **`base.dtb`（222,346 B → 221,460 B）**：
  - 删除 3 个调试/监控节点：`/ddr_profile_monitor`、`/dvfs_track`、`/soc/ddr_pattern_trace`（及 `/__symbols__:pattern_trace`）；
  - `/vote_mng_test` 新增 `status = "disabled"`；
  - 其余全部 1,052 个节点、时钟、电源、内存与保留区拓扑完全不变（其余差异均为删除 3 节点引发的 phandle 编号平移）。
- **`dtbo.img`（8 个 entry）**：
  - `entry00`–`entry06`（含 O2S PHONE 命中的 `entry05_id090f0000_rev0`，358,871 B）逐字节相同；
  - 仅 `entry07_id09020101_rev0`（O81A PAD，266,062 B → 266,111 B）在 `fragment->&xring_dp_display/__overlay__` 新增一条 `signal-table = <0x1 0x1 0x0 0x0 0x32 0x10>`。

三代共计 3 份 `base.dtb` + 24 份 `.dtbo` 在宿主 `dtc 1.8.1` 下 `dtc -I dtb -O dts` 后再 `dtc -@ -I dts -O dtb` 回编，全部逐字节 SHA-256 一致。

## 3. `tools/fdtdiff.py` 规格化修复说明

旧版 `fdtdiff.py` 存在三类失真：`phandle` 自身数值变化污染统计；对 `clocks`/`mboxes`/`iommus` 等混合引用列表不按目标 `#*-cells` 步进解析，且 `'opp-'` 前缀误把 `opp-millivolt` 中的电压标量当成 phandle；`--overlay` 模式把所有 `target = <&sym>`（二进制值为 `0xffffffff`）都映射为同一个 `phandle#4294967295` 键而互相覆盖。

新版修复要点：
1. 默认忽略 `phandle` / `linux,phandle` 属性本身；
2. 收集提供方 `#*-cells` 步进解析 `(phandle, specifier...)` 元组，新增玄戒私有 `vote-mngs`（1 specifier cell）、`hwlocks`、`asoc-*` 等支持，剔除标量属性误匹配；
3. 解析 `/__fixups__` 把外部 `target` 还原为真实符号名（如 `&xring_dp_display`），对同目标多 fragment 追加 `#N` 消歧后缀。

## 4. `.dtso` 增量补丁与安全打包流

- 日常适配写在 [`overlays/custom/`](../../overlays/custom/)（`.dtso`），通过 `make b overlays` 编译后由 `fdtoverlay` 叠加到 `base.dtb`。注意标准 FDT overlay 无法删除 base 中已有的属性（`/delete-property/` 在独立 `.dtso` 内仅作用于当前节点，不会删掉 base 属性）。
- 重打 `vendor_boot.img` 统一使用 [`scripts/pack-vendor_boot.sh`](../../scripts/pack-vendor_boot.sh) `--stock-img <基底镜像> --dtb <新dtb> --pad-to-stock`，动态继承底包自身的 `ramdisk_offset`、`dtb_offset` 与 `vendor_cmdline`，禁止跨代硬编码 OS3 参数。
