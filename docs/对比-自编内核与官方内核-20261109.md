# 对比：自编 6.18 内核 vs 官方 OS4 内核（2026-11-09）

| 维度 | 官方 OS4 内核 | 我们自编的内核 | 影响 |
| --- | --- | --- | --- |
| 版本 | 6.18.21-android17-5-g1d099fcb35e0-abogki538445360-4k | 6.18.21-4k-g5a4f1906ff98 | 仅版本串不同，功能一致 |
| 源码 | AOSP 6.18.21 + 小米私有补丁 | AOSP android17-6.18-2026-06（6.18.21），无厂商补丁 | 厂商补丁带来的行为差异未知，但实测可日用 |
| 工具链 | clang r584948c（22.0.1）+ rust 1.91.1.p3 | 同款 | 一致 |
| 配置 | 设备 `/proc/config.gz` | 同左，仅 7 项厂商私有选项被丢弃 | 见下 |
| 导出符号 | 9,090 个 | 约 3,900 个（按模块导入白名单 TRIM） | 第三方模块可能缺符号；原厂 542 模块不受影响 |
| 模块签名 | 小米密钥 | 我们构建时生成的密钥；`MODULE_SIG_FORCE=n`，原厂模块仍可加载 | 未签名模块不能引用受保护符号 |
| `rust_binder` | 原厂签名模块可加载 | 原厂模块因 crate 哈希不匹配加载失败；用自编并签名的模块替代 | 当前手动 insmod，refcnt 0 |
| AVB/verity | orange / enforcing | 不变 | boot 未签名，解锁状态可启动 |

## 被丢弃的 7 项配置

| 配置 | 作用 | 是否性能相关 |
| --- | --- | --- |
| `F2FS_VIP_FILE` | f2fs 的 VIP 文件保留策略（小米私有） | 是，存储/数据保留行为 |
| `F2FS_INLINE_EXTENT` / `_DEBUG` | f2fs inline extent 优化（小米私有） | 是，存储性能 |
| `SCSI_DISCARD` / `SCSI_FASTDISCARD` | SCSI/UFS discard（TRIM）支持 | 是，存储性能 |
| `XIAOMI_ENHANCED_IOSTAT` / `XIAOMI_EROFS_IOSTAT` | 小米增强 I/O 统计 | 统计口径，性能间接 |
| `UAPI_HEADER_TEST`、`CC_CAN_LINK` | 构建/自检类开关 | 否 |

以上这些在 AOSP 源码里没有实现，属于小米私有补丁；我们的内核不包含，日常感知不到，但存储性能和统计行为可能有差别。

## 换第三方系统能不能吃到这些

这些是**内核侧**特性，跟内核和 vendor 模块走，不跟 system/rom 走。所以：

- 第三方 ROM 如果保持小米原厂内核（或原厂 6.6.30 vendor 内核）→ 这些特性还在，能吃到；
- 第三方 ROM 如果用 AOSP/OSS 自编内核（比如我们这版）→ 没有，除非把厂商补丁移植进来；
- 换 system 分区本身不会带来或带走它们。
